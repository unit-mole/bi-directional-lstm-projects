# Data Notes

## Supplied source file

The attached `resume_dataset.csv` contains eight short example resumes with two columns:

- `Category`
- `Resume_str`

It is copied to `data/raw/resume_dataset.csv` for traceability.

## Portfolio-safe demonstration data

Because eight rows are not enough to validate a neural matching system, this project creates a transparent synthetic demonstration set:

- `data/sample/sample_resumes.csv` — the eight supplied example resumes with generated IDs;
- `data/sample/sample_job_descriptions.csv` — synthetic job descriptions across the same seven categories;
- `data/processed/resume_job_pairs.csv` — balanced positive and negative pairs generated by the training script;
- `data/sample/sample_resume_job_pairs.csv` — safe examples for the Streamlit interface.

Job-description template index determines the split: templates 1–6 train, template 7 validation, and template 8 test. This avoids identical job descriptions appearing across partitions, although the same small set of resume examples remains present. Reported metrics are therefore demonstration metrics, not evidence of real-world generalization.

## Privacy and redistribution

Do not commit real resumes, names, email addresses, phone numbers, home addresses, LinkedIn URLs, GitHub URLs, immigration information, protected attributes, or confidential job descriptions. Use synthetic or properly anonymized examples only. Store any authorized private data outside Git and apply access controls, retention limits, and legal review.
